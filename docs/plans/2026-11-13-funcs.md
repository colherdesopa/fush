# Milestone: functions + abbr

Design ref: docs/DESIGN.md "After the PoC" item 2. Predecessors: PoC
(2026-11-13-poc.md), UX milestone (2026-11-13-ux.md), both complete at 952e727.

## Goal

Fish-style user-defined functions and abbreviations, interactive-first:

```
function greet
    echo hello $argv
end
greet world          ; -> hello world

abbr -a gs git status
gs<space>            ; expands to: git status<space>
```

## Task 1 — parser: `function` blocks

Extend src/parser.rs + src/ast.rs:

- `Stmt::Function { name, params, body }` parsed from `function NAME [ARG...]...  body... end`
- `function` is a contextual keyword (bare unquoted unescaped word), like
  if/for/while/switch. The word after `function` is the function NAME (bare
  word, not expanded). Remaining words on the line are PARAMS (stored as
  literal strings; fish calls them $argv but named args are out of scope —
  store them, ignore them at runtime for now, they exist so the parse doesn't
  reject `function foo --description x`). Body is statements until `end`,
  same machinery as parse_block_start.
- Nested function definitions inside a function body parse (body is just
  stmts).
- Unit tests: basic definition parses with name/params/body; missing name →
  error; missing end → incomplete error; nested definition; params with
  dashes; `function` as an argument position word (`echo function`) does NOT
  trigger.

## Task 2 — runtime: function table + `functions`/`return` builtins

Extend src/runtime.rs, src/exec.rs, src/builtins.rs:

- `Runtime` gains `functions: HashMap<String, Rc<Stmt::Function payload>>`
  (Rc so recursion doesn't deep-clone; pick the concrete type that fits the
  existing AST ownership — document the choice).
- `run_stmt` handles `Stmt::Function` by registering the definition
  (redefinition overwrites; fish prints a warning, we skip that).
- Command dispatch: after builtins, before PATH search, check the function
  table. Function call semantics:
  - Push a fresh local scope; bind `$argv` to the call args (list); bind
    `$argc` to the count (fish doesn't have $argc — SKIP it, only $argv).
  - Params from the definition line are NOT bound (stored only).
  - Execute body via run_stmts; `return` builtin (new) stops body execution
    with $status of the last command (or explicit `return N`); pop scope.
  - Function status: $status of last body command; `return N` sets it.
  - Recursion depth cap 100 → error "function call stack exceeded" (status 1),
  prevents infinite recursion from hanging the shell.
- New builtins:
  - `functions` (no args): print known function names, one per line, sorted.
  - `functions NAME`: print the definition source if we can (PoC: print
    `function NAME ... end` skeleton with params; exact source not kept —
    document this limitation).
  - `return [N]`: inside a function, stop body (as above); at top level,
    fish errors — we set $status and continue (document).
- Highlight: function names color as commands (cyan when defined) — extend
  src/highlight.rs is_external path to also consult a defined-functions
  check. The highlighter runs on a line without runtime state; for PoC,
  functions defined in the SESSION are unknown to the highlighter — acceptable,
  document. (Skip if it requires threading runtime state through the Helper;
  note it in the report.)
- Unit + integration tests: define+call, $argv list, return with/without N,
  nested calls, recursion cap, functions builtin output, redefine
  overwrites, function shadows external command of same name (fish
  semantics: functions > builtins? NO — fish: functions shadow externals,
  builtins shadow functions; verify and match fish: builtin wins).

## Task 3 — abbr: builtin + expansion

Extend src/builtins.rs, src/repl.rs:

- `abbr` builtin: `abbr -a NAME VALUE...` adds; `abbr -e NAME` erases;
  `abbr` lists `name value...` lines; `abbr NAME` shows one. Store in
  Runtime (persist later with config home — out of scope).
- REPL expansion: on accepted line (before parse), find the FIRST word in
  the line; if it matches an abbreviation, replace it with the expansion.
  fish expands on space when the cursor is after the word — we expand on
  Enter for the whole line (simpler, still useful; document the tradeoff).
  Expansion applies to interactive lines only, NOT to -c or script mode
  (fish does it interactively too).
- Highlight integration: none (the abbreviation is replaced before parse).
- Tests: abbr add/list/erase; expansion in REPL path (unit-test the
  expansion function directly with a line + abbr table; the REPL loop
  itself stays thin); -c mode does NOT expand.
